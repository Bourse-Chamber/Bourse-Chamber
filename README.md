**Bourse Chamber** ([www.boursechamber.tech](https://www.boursechamber.tech)) is an institutional-grade, multi-agent AI deliberation platform designed for digital asset governance and crypto investment intelligence.

Instead of relying on single-prompt black-box LLMs, Bourse Chamber convenes an unyielding floor of **nine canonical crypto architects, founders, and economic theorists**. The council puts any crypto asset, narrative thesis, or token contract address (`TOKEN_CA`) through structured, adversarial multi-round debate — concluding in immutable, on-the-record roll-call votes archived in a permanent **Verdict Ledger**.

---

## 🏛️ Core Value Proposition

In a crypto ecosystem saturated with speculative noise, memecoin velocity, and narrative rotation, capital allocators face severe information asymmetry. Traditional dashboards only track superficial price action or paid social metrics.

Bourse Chamber resolves this through an objective, multi-perspective adversarial council:

* **Adversarial Multi-Agent Deliberation:** Nine distinct crypto personas evaluate assets independently before clashing in structured cross-examinations. Consensus cannot form without withstanding hostile scrutiny.
* **Objective TOKEN_CA Feasibility Auditing:** Priority 1 detection for EVM and Solana contract addresses. Quantifies required market cap expansion multiples against DEX liquidity depth, LP lock verification, and deployer mint authority risk.
* **Strict Evidence Handling (`DATA UNAVAILABLE`):** The engine prohibits fabricated data. If contract audits, liquidity pools, or historical distribution cannot be verified, votes strictly default to `INSUFFICIENT_EVIDENCE`.
* **Deterministic Supermajority Rules:** Major recommendations (`ADD` / `REDUCE`) require an asymmetric 6-of-9 supermajority burden of proof. Ties and unproven claims strictly default to `PASS`.
* **Permanent Unalterable Verdict Records:** Every deliberation is cryptographically assigned a session ID (`BC-XXXX`) and archived in an immutable, shareable ledger with dynamic 1200×630 Open Graph preview cards.

## ⚖️ The Deliberation Engine & TOKEN_CA Rubric

### Three-Stage Council Protocol

```
┌─────────────────────────────────┐
│   Round 1: Independent Reads   │  Nine seats evaluate evidence pack in strict isolation.
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│   Round 2: Cross-Examination    │  Moderator identifies acute divergence; convenes direct clash.
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│   Round 3: Binding Roll-Call    │  All seats cast recorded votes with immutable governing rationales.
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│   Verdict Aggregation & Ledger  │  Deterministic supermajority calculation, Taleb sizing, & permanent record.
└─────────────────────────────────┘
```

### Voting Standards & Outcomes

Depending on whether the inquiry is a **Macro Thesis** or a **Token Contract Audit (`TOKEN_CA`)**, the council votes under calibrated standards:

| Inquiry Type | Valid Ballots | Decision Threshold | Default Fallback |
|---|---|---|---|
| **Macro / Core Asset** | `ADD` · `REDUCE` · `PASS` | $\ge 6 / 9$ Supermajority (66.7%) | `PASS` |
| **TOKEN_CA Feasibility** | `SUPPORTED` · `NOT_SUPPORTED` · `INSUFFICIENT_EVIDENCE` | $> 50\%$ Majority of participating seats | `INSUFFICIENT_EVIDENCE` |

### Taleb Position Sizing Bands
- **0.5% – 1.0%:** Highly speculative, nascent network velocity, or unverified custody.
- **1.0% – 2.0%:** Intermediate structural moat with measurable execution risk.
- **2.0% – 3.5%:** Strong network fundamentals and proven liquidity depth.
- **3.0% – 5.0%:** Core institutional sovereign asset grade (reserved for supermajority `ADD` outcomes).
- *Note:* Position sizing is automatically suppressed on pure contract feasibility audits unless explicitly requested.

## 💻 Tech Stack

### Frontend Architecture
- **Core Technology:** HTML5, CSS3, Vanilla JavaScript (ES6+ modular controllers).
- **Aesthetic:** Brutalist Monochrome Financial Terminal (`#050505` obsidian canvas, `#FFFFFF` crisp type, `#242424` institutional borders).
- **Typography:** JetBrains Mono (monospaced metrics/code) & Inter (high-legibility editorial text).
- **Visuals & Avatars:** Deterministic inline SVG pixel avatars generated dynamically from persona seeds.
- **SSR / Dynamic Previews:** Next.js App Router for server-rendered verdict records and dynamic OG cards.

### Backend & Serverless
- **Serverless Runtime:** Next.js Serverless Functions / Node.js.
- **AI Orchestration:** OpenRouter API routing across leading frontier LLMs (Claude 3.5 Sonnet, GPT-4o).
- **Market Telemetry:** CoinGecko Pro API integration with automatic normalization and data-gap fallbacks.
- **Database:** PostgreSQL / Supabase enterprise schema + portable zero-dependency LocalStorage client caching.
- **Automation:** Vercel Cron (`/api/cron/watcher`) for automated daily price drawdown monitoring.

## ⚙️ Getting Started

### Prerequisites
- Node.js (v18.0.0 or higher)
- npm (v9.0.0 or higher)

### Quick Start

1. **Clone the Repository:**
   ```bash
   git clone https://github.com/davitzarly/Bourse-Chamber.git
   cd bourse-chamber
   ```

2. **Install Dependencies:**
   ```bash
   npm install
   ```

3. **Configure Environment Variables (`.env.local`):**
   ```env
   OPENROUTER_API_KEY="your-openrouter-api-key"
   CRON_SECRET="your-secure-cron-secret"
   COINGECKO_API_KEY="your-optional-coingecko-key"
   ```

4. **Run the Development Server:**
   ```bash
   npm run dev
   ```
   Open `http://localhost:3000` in your browser.

5. **Static Server Option (Zero Dependencies):**
   You can also serve the static HTML files directly:
   ```bash
   npx serve .
   ```
